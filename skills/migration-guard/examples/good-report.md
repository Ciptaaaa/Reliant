# GOOD — a conforming report

The report body lives in [`good-report.report.md`](good-report.report.md): a byte-for-byte conforming
report that CI lints. This page explains it and shows the input.

```bash
python scripts/linter_report.py skills/migration-guard/examples/good-report.report.md
```

`bad-report.md` covers the same migration and reaches the same conclusion. It is rejected. Only the
structure differs, and that difference is the whole point: one report can be checked, diffed between
runs, and gated before merge; the other cannot.

## The input (not part of the report)

The input is deliberately generic and does not correspond to any test case.

```sql
-- db/migrate/20261116140000_remove_fax_from_customers.sql
ALTER TABLE customers DROP COLUMN fax;
```

```sql
-- schema.sql (PostgreSQL 16, ~120,000 rows, ~9,400 non-NULL fax)
CREATE TABLE customers (
    id    bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name  text NOT NULL,
    fax   varchar(32)
);
```

`application-usage.md`: `app/controllers/customers_controller.rb:44` reads `fax` for the invoice
letterhead. Nightly `pg_dump`, 24h RPO.

## Why the conforming report is the right one

| Temptation | What `good-report.report.md` does instead |
|---|---|
| `### 1. Application still reads the column` | Tags it `### F1 — BLOCKER — destructive-column-drop`, so severity and category are fields, not prose |
| "the column is still used" | Quotes `app/controllers/customers_controller.rb:44` and the data fact from `schema.sql` |
| "needs review before merge" | States `**Approval**: accept-risk` and names the restore point |
Three properties make it safe to automate over:

1. **Every finding is addressable** — `F1`, `F2`, each with one severity. A diff between two runs is
   meaningful because the units are stable.
2. **Every claim has an address** — a `path:line` a reviewer can open, including `migration.sql:2` for
   the statement itself.
3. **Every irreversible step has a gate** — `Approval: accept-risk` plus a restore point, which is what
   makes the drop reviewable by a human instead of trusted from a model.
